# Security review — 2026-10-26

This is a targeted source and dependency review prompted by CVE-2026-111497,
not a full penetration test or verification of deployed services.

## Findings and changes

| Area | Evidence | Remediation |
| --- | --- | --- |
| Node/Brotli | API outbound `fetch()` calls in notifications and App Store Connect, plus OAuth/JWKS network clients, can receive compressed responses. Containers used floating `node:22-slim`; Pages CI used Node 20. | API and UI container stages pinned to Node 22.23.4; `.nvmrc`, package engine floors, and CI updated. Image builds explicitly pull fresh base images. |
| npm dependencies | API: 13 affected packages (one critical); UI: six (one critical), including Auth.js, Fastify, Next.js, and transitive build dependencies. These are scanner findings, not proof every advisory is reachable. Production UI is a static export with image optimization disabled. | Auth.js 0.41.3, Swagger UI 6.1.2, Fastify 5.12.7, Next.js 16.4.3, and refreshed compatible lockfile dependencies. Both complete lockfile audits report zero findings. |
| Token secret | The Bearer-token key derivation accepted an absent/empty `AUTH_SECRET`, producing a predictable encryption key. | Refuse missing/blank secrets during key derivation and before the API starts listening. Regression tests cover missing/blank secrets and token rejection with another secret. |
| Mobile account linking | A signature-verified ID token's email was used for cross-provider account linking without checking `email_verified`. | Require nonempty string subject/email and an explicitly verified email before account lookup or linking. Tests cover rejected claims for both providers and accepted boolean/string verification claims. |
| Apple callback | Name backfill used an untrusted callback email, ran even after failed authentication, and could update another account's unset name. | Run backfill only in Auth.js's successful Apple sign-in event and select by the authenticated user ID. Regression tests cover failed callbacks and a forged victim email. |
| Python | No declared Brotli/brotlicffi dependencies or extras in the three requirements sets. Ambient optional installations can still enable automatic response decoding. | Add constraints for Brotli >=1.2.1 and brotlicffi >=1.2.1.0 without installing either decoder. Constraints apply to dependency resolution; they do not upgrade an already-installed optional package unless it participates in that install. |
| Documentation dependencies | pip-audit found mkdocs-material and pymdown-extensions advisories. | Upgrade Material to 9.7.7, require pymdown-extensions >=11.0.1, and make the docs-local installation target use the requirements file. All three requirements audits now pass. |
| UI Docker context | `COPY . .` had no `.dockerignore`, allowing local dependency/build output and environment files into the builder. | Exclude node_modules, generated build output, and `.env` files. |

Weekly and pull-request dependency audits now cover both npm lockfiles and all
three Python requirements sets. Audits use the advisory databases available at
execution time; a clean result is not a guarantee against undisclosed issues.

## Platform scope

- Android: inspected `:app:dependencies --configuration debugRuntimeClasspath`.
  No Brotli, brotli4j, Cronet, or Netty dependency appeared. No application-owned
  Brotli decoder was found in source. This is not a complete Android CVE audit.
- iOS: no bundled Brotli dependency found in source or declared Swift packages
  (ZIPFoundation, GRDB, GoogleSignIn, and local SwiftAudioStreamEx). OS-provided
  URLSession/WebKit decoding remains Apple's responsibility. iOS was not built
  or scanned for all dependency advisories on this Linux machine.
- Caddy: configuration does not enable a Brotli request/response decompressor.
  Its Go runtime and OS packages were not subjected to a full image CVE scan.
- No deployed container, server OS, remote Mac, CI runner system libraries, or
  end-user mobile OS has been certified patched by this review.

## Local machine and deployment work still required

The initial local checks found Node **24.15.0** with Brotli **1.2.0**, and Python
Brotli **1.2.0** at `/usr/lib64/python3.14/site-packages`. Both need remediation.
Follow-up remediation: the global mise Node selection was upgraded to **24.22.1**,
with the download signature verified using a temporary GPG keyring to bypass an
existing stale keyring lock. This patched Node build reports bundled Brotli 1.2.0;
the Node release version establishes that the decoder fix is present.

Created `data/scripts/.venv` with system-site-packages disabled and installed the
data pipeline requirements. Verified neither Brotli nor brotlicffi is importable
there. Activate it before running local pipeline commands:

```sh
source data/scripts/.venv/bin/activate
```

Fedora 44 enabled repositories were checked and still offer only
`libbrotli-1.2.0-3.fc44` and `python3-brotli-1.2.0-3.fc44`. The system packages
remain unpatched; no system-managed files were overwritten. Passwordless sudo
is unavailable.

1. Restart existing Node development processes so they use the newly selected
   24.22.1 runtime. `.nvmrc` selects patched 22.23.4 for tools that honor it.
2. Update or remove optional Python Brotli/brotlicffi in **each active virtual
   environment**. Use the OS vendor's security-fixed package for system-managed
   bindings. Do not overwrite distribution packages with system-wide pip.
3. Rebuild and deploy the API/UI/Caddy images, restart affected services, and
   verify the actual running API Node version. Repository changes do not patch
   existing containers. Existing release/deploy Make targets are unchanged.
4. Inventory host/container libbrotli and curl separately using vendor advisories;
   vendors may backport fixes without changing the apparent upstream version.
5. Smoke-test Google and Apple sign-in on web and mobile after deployment. Tokens
   without a verified email will now be rejected. Confirm a strong, random
   `AUTH_SECRET` is present. No OAuth credentials were used for this review.

Verify a deployed API runtime without printing configuration secrets:

```sh
docker compose exec -T api node -p 'JSON.stringify({node:process.version,brotli:process.versions.brotli})'
```

Use the Node security release version as the primary check. The tested patched
Node 22.23.4 image reports Brotli 1.1.0; a bundled-library version string alone
cannot distinguish a backported fix.
